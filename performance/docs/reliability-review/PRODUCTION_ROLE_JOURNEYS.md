## 1. Required identity and data dependencies

Use normal production Seemplify OIDC with separate synthetic accounts in a clearly named acceptance organization. Record actual central grants, active organization, managed teams/department and selected-reviewer eligibility. Never manufacture browser cookies/claims or expose the loopback fixture login in production. No ordinary staff, real employment outcomes or actual customer files belong in this run.

| Provisioning dependency | Minimum useful setup / purpose |

Priority order: **identity/scope → goal period and approved goals → role-scoped launches → employee/reviewer completion → discussion/calibration/finalization → history/report → talent/analytics**. Support/development and recognition/feedback can run alongside once identities and safe recipients exist. External calendar/call/AI cases need their own prerequisites below.

## 4. Production evidence, genuine external limits and closeout

For every role, record **actual signed-in role + organization + server-granted scope**, not a renamed local session. Capture privacy-reviewed synthetic screens, visible stage changes, authorized downloads, network failures and final persisted reload. Required denials must leave no unauthorized record, event or newly signed file link. Unexpected 4xx/5xx or a fake empty result is a defect; capture the response privately before repair. Production user-facing error recovery can be exercised with bounded browser-only interception; report that substitute explicitly and never manufacture a server outage.

Keep these independent proof branches honest:

- **Calendar/email/chat:** adapter success or persisted notification/outbox is not actual delivery. A completed branch needs a controlled receiving inbox/channel/calendar and cancellation/cleanup; no real staff destinations.
- **Native media/TURN:** two actual browser peers, consent, join/rejoin/leave, real relay path, recording upload/conversion/playback and cleanup are distinct. A TURN credential 200 or local peer connection does not establish relayed connectivity. Report browser media/device/permission prerequisites and provider limits.
- **Transcription/AI:** require an actual configured provider, authorized synthetic content and effective account/organization/cycle consent; verify result provenance and human approval. An unavailable provider or unconsented account is an external blocked branch, not a reason to bypass controls. Manual assessment still must finish.
- **Learning/private scanner/retention:** distinguish real upstream Learning delivery and actual scanner from local fixtures; legal-hold/retention policy must remain intact. Do not erase evidence or alter global policy to simplify cleanup.
- **Load/full restore:** this browser programme establishes named transactions, not capacity, disaster recovery or every possible production account. Full production restore remains separately uncertified.

Finish by restoring test-org options/preferences, cancelling synthetic pending jobs/meetings, verifying removed Cloudinary test assets and recording any retained audit/history. Refresh the final receipt with **per-role journey IDs, completion/denial screenshots and remaining provider blocks**. Do not label seven-role production acceptance complete while any required role remains merely provisioned or has only loaded a page.
