# Performance Management: before, concept and final

Open [the visual gallery](VISUAL-COMPARISON.html) to inspect all 68 existing page templates side by side. Search by route, open an original screenshot at full size, and follow the concept reference attached to each page.

## How the comparison works

1. **Before:** an isolated default production build of pre-redesign commit `a93ddbf9`, exact source tree `8f97b7f88ded397c3d291158645b6fe138c3cad6`.
2. **Desired:** two explicitly labeled generated proposals, for the dashboard direction and responsive competency direction. These are shared visual references, not 68 individual page mockups.
3. **Final:** an isolated default production build of exact combined source tree `7eb9c096330d19b1a854c0f45fa15d0583f09c13`, incorporating the separately committed AI assessment work intact.
4. **Verdict:** an independent route-specific assessment of hierarchy, readability, density, actions and deliberate differences from the concept. A modest visual refinement is described as such.

Before and final use the same controlled synthetic records and matching viewport/theme where compared. A previously missing fixture, authentication guard or recovery state is not counted as a design improvement over a populated page. The full register retains those historical attempts separately.

## Concrete findings and repairs

| Finding | Implemented response | Proof |
| --- | --- | --- |
| Mobile People cards crowded identity, metrics and actions | Separate responsive rows; long text wraps; New 1:1 joins page actions and clears the Guide | Native member-card pair, six viewport/theme captures and action/geometry checks |
| Team OKRs summary and narrow table were hard to read | Measured caption contrast, genuine zero preserved, unknown count omitted, named keyboard-scrollable table | Four repaired views and focused keyboard/contrast checks |
| Dark conversation Send icon and content materials were inconsistent | Theme contrast foreground and opaque content/composer surfaces | Matched conversation captures and computed style/contrast checks; synthetic transport only |
| Competency selection competed with the main action | Current section has a text/underline indicator; real API versions are displayed only when present | Populated role captures, strategy metadata proof and focused checks |
| The initial dashboard comparison used different screenshot extents | Native equal 1440 × 1000 viewport captures | Unmodified before/final images in the PDF and evidence ledger |

The [core review](VISUAL-COMPARISON-CORE.md) covers 33 exact templates; the [growth review](VISUAL-COMPARISON-GROWTH.md) covers 35. Their judgments are visual review, not measured user research. [SCREEN-COVERAGE.md](SCREEN-COVERAGE.md) records additional mobile, dark, dialog, keyboard, zoom and print views and their source boundaries.

Authenticated production screenshots and role checks are a separate evidence set, documented in the [delivery receipt](DELIVERY-RECEIPT.md). Synthetic conversation rendering does not establish a real AI or external-provider execution.
