## Story and current problem

As an authorized employee, reviewer or HR reader opening `/appraisals/[appraisalId]/report`, I want to understand the saved outcome, competency comparisons, frozen goal outcomes and evidence limitations at a glance, then read the relevant explanation and complete record, so that I can discuss the result without searching through a long narrative.

## Existing data contract and honest limits

| Available field | Appropriate display | Must not imply |
|---|---|---|
| `finalRating.overall`, `ratingLabel`, `justification`, `finalizedAt`; `ratingScale.min/max` | Saved outcome and actual configured range, short rationale, full rationale drilldown | AI result replaces the human outcome; fabricated percentile/trend |
| `managerFeedback.overallRating`, author, submittedAt | Separate submitted reviewer rating with attribution/date | An overall employee self-rating: that field is absent from this DTO |
| `competencies[]`: name, selfRating, managerRating, managerComments | Grouped horizontal employee/reviewer bars and exact numeric labels; explanation next to/below each criterion | A radar polygon, ranking, confidence, missing-value zero, or temporal improvement |
| `goals[]`: title, nullable score | Frozen captured achievement bars with `%` and exact values; rated/total count | Current live OKR progress or a recalculated final rating |
| `managerFeedback.goals[]`: id/title/comments/verifiedCompletion/qualityRating | Reviewer completion/quality/comments as distinct labeled detail, if shown | A reliable join to frozen goals by title; frozen goal entries have no matching ID. Quality and achievement are different units |
| `aiReport.coverage`: meetings, transcripts, documents, pendingDocuments, roleResults, source refs/states, missing transcripts, gaps, excerptedCategories | Evidence counts, explicitly named missing/pending/excerpted evidence, complete source drawer | A confidence score, completeness percentage, evidence quality score or synthetic total denominator |
| Employee/manager summaries, discussion, submitted custom answers, documents | Short source-labeled written findings, then keyboard-expandable full records | Generated recommendations or extracted numeric scores that the API did not supply |
| `aiReport.content/state/generatedAt/model` | Clearly attributed AI analysis with short preview and expandable full content/sections | Structured AI summary fields, verified facts, hidden truncation or chart values parsed from prose |
| Linked competency report | Separate existing protected/frozen report disclosure with preserved version/export controls | Combining its native framework levels or numeric strategy measures into the appraisal scale |

Missing/null/nonfinite values show **Not rated**, **Not recorded** or **Coverage unavailable** as appropriate, and no bar. Genuine numeric zero is preserved when valid for its field/domain. Never coerce null/empty strings to zero, clamp the displayed source value, or invent absent denominators. Architect must confirm rating ranges and any out-of-domain legacy rendering before implementation acceptance. Invalid/out-of-range historical values remain explicitly unavailable to chart rather than silently altered. Do not derive an aggregate rating from criterion or goal averages. If a simple mean is used for a descriptive goal metric, label it **unweighted mean of N rated frozen goals**, exclude unrated entries from the denominator, and do not present it as the final score; omitting that mean is preferable to unclear semantics.

## Intended composition

1. **Compact report header.** Employee, cycle/period, reviewer, saved final result/label, finalized date and acknowledgement. Keep Back/Open/CSV/Print utilities together. One strongest outcome number; remaining metadata is secondary. Short saved final rationale stays visible alongside the outcome, with full text available if long.
2. **Competency comparison.** Main analytical panel: readable criterion names, consistently ordered Employee/Reviewer series, reported scale ticks and direct values. Grouped bars or a paired-point/dumbbell plot are acceptable; the latter can show the nonzero reported minimum honestly without implying a zero-based bar. Beside it on wide screens, a concise written assessment sourced from recorded manager summary/comments, with source label and full-record disclosure. On mobile stack chart then explanation; wrap names, keep marks and value labels readable. No chart animation necessary.
3. **Frozen goal outcomes.** A separate horizontal achievement chart/list, exact percentages, goal name and rated/total count. Explain that these are saved appraisal goal snapshots. Written reviewer findings remain adjacent as separate sourced text, without unsafe title joins. Sparse one-row data remains a useful labeled bar, not fake history. No data produces a useful honest empty state.
4. **Evidence used and limitations.** Compact labeled counts, missing/pending warnings and source-list disclosure. Count labels retain units; they are not a ring claiming overall completeness. Display stated evidence gaps without forcing readers to open a long AI narrative.
5. **Written analysis and full record.** AI analysis has a brief preview and collapsed full section(s), labeled generated/model/date and human-decision distinction. Employee reflection, manager submission, discussion/next steps, submitted question answers, supporting documents and linked competency report remain available in meaningful titled disclosures. Open only a small useful summary by default. Never remove recorded content or require regeneration to recover it.

Use existing MUI foundations and shared semantic tokens: system type, neutral/opaque panels, restrained borders, blue interactive emphasis and a second distinguishable chart series. Charts use direct labels and legend/series names as well as color; status colors do not encode an invented judgment. Avoid a wall of tiny metric cards. The expected initial desktop experience shows saved outcome and the first substantive chart without scrolling through AI prose.

### Numeric-contract clarification from retained architect

Saved goal achievement and reviewer verified completion each use 0–100, while reviewer goal quality is a distinct fixed 1–5 measure. Overall and competency ratings use the DTO's **reported rating scale**. Its source can fall back from saved snapshot to live cycle to 1–5, and no provenance flag is exposed; the UI must not claim that this scale is guaranteed frozen. Meeting and transcript counts overlap and must not be stacked or summed as independent evidence categories. Exact missing-state handling and native linked-report scales remain as specified above.

Print review must account for existing CSS that forces all backgrounds white: bars need print-safe explicit fills/strokes and direct numeric labels; a white bar on white is not acceptable. All graph rows must print even if screen composition has a row limit/disclosure.
