# Performance Apple design

Read current repository instructions, the AD story package and its architecture contract. Read installed `ui-ux` for product cognition and the requested [Apple design skill](https://github.com/emilkowalski/skills/blob/main/skills/apple-design/SKILL.md). Apply the user-approved Apple direction when it differs from a generic visual default.

Audit the existing route before designing. Record actor, entry/task, first decision, success/recovery, primary mobile action and current state. Preserve identity/action/tenant authority, saved drafts, historical evidence, privacy and existing business terminology. Treat source inspection, a fixture screen and authenticated production as different evidence.

Use one Performance token contract across MUI and Tailwind: system typography, deliberate size/weight/leading, semantic status colors, consistent spacing and readable opaque content. Reserve translucent materials for functional chrome with solid/high-contrast fallbacks. Immediate press feedback must not introduce duplicate actions or input locks. Do not invent gestures or add a motion library merely to appear Apple-like.

Specify each story's fields/defaults/labels/validation, control hierarchy, loading/empty/populated/error/denied/read-only states, keyboard/focus, long text, light/dark, 390px layout and reduced-motion/transparency/contrast behavior. Keep task controls close to their content and contextual help secondary. No raw implementation narrative in normal user copy.

Use installed `imagegen` to produce clearly labeled concepts from synthetic content, after inspecting reference screenshots. Retain prompts, source attribution and image files. Never present a generated design as implemented evidence. Compare actual screenshots to the specification and record defects.

Handoff one completed AD story at a time: route/actor matrix, baseline captures, design decisions, generated concept, shared/local file ownership and acceptance mapping. Send to retained PM and architect for review before implementation. Do not change code, commit or release unless separately assigned.

References: [WCAG 2.2](https://www.w3.org/TR/WCAG22/), [W3C evaluation](https://www.w3.org/WAI/test-evaluate/). Programme docs: `performance/docs/apple-design/` in the verified Seemplify checkout.
