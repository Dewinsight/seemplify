# Growth screens: before, desired direction and current implementation

Independent second visual review by PM2 / UI-UX2, 21 October 2026. **35 exact route templates reviewed against matched pre-redesign and fresh final screenshots.** This review distinguishes visible affordance gains from modest visual refinement; it does not label every page a structural redesign.

## Overall judgement and concept gap

22 routes show a visible affordance/hierarchy improvement; 13 are visual refinements of an already workable composition. All 35 use matched body states. The strongest repeatable gains are quieter help, a single task-action emphasis, visible input boundaries, more legible status badges and underlined competency wayfinding. The underlying business layout is deliberately preserved in many routes.

The populated [matched desktop before](evidence/comparison-baseline/growth-populated-competency--roles-desktop-light.png), [current desktop](evidence/final-comparison/growth-populated-competency--roles-desktop-light.png), [current light mobile](evidence/final-comparison/growth-populated-competency--roles-mobile-light.png) and [current dark mobile](evidence/final-comparison/growth-populated-competency--roles-mobile-dark.png) make the adoption and gap inspectable. The underline leaves New role as the sole solid task action, search/status edges are clearer and Published/Open role remain readable. Card rows are a justified adaptation of the existing product: identity, metadata and action fit at 390px without a wide table. They are not a compact-table redesign. The numeric role version and descriptive summary shown by the concept are not present in the aggregate contract, so they are not invented.

[Matched four-mode role receipt](evidence/comparison-baseline/growth-populated-concept.json) and [current four-mode role receipt](evidence/final-comparison/growth-populated-concept.json) use the same explicit aggregate role fields: id, name, revision, currentVersionId and updatedAt, with no numeric version. Current checks pass one aria-current, original href, transparent active background, 2px underline, 42.5px target height, keyboard focus-visible 2px outline and omitted unavailable role version in all four modes. Actual finite strategy version is shown; role revision is never relabeled as version. The provisional fixture that mixed a version-row shape into aggregate roles was archived, corrected and is not current comparison evidence.

[Strategy metadata proof](evidence/final-comparison/growth-strategy-proof.json) additionally asserts the exact current row text “Strategic outcome criteria · v1”, the actual existing finite strategy version and absence of the incorrect cycle subtitle. [All-screen current index](SCREEN-COVERAGE.md) joins the 35 growth templates to the 33 core templates under one current build tree.

This comparison led to two small PM/architect-approved presentation changes: underlined current competency navigation, and display of a numeric version only when the actual existing list response supplies one. No role/version API join, new business field or permission change was added. The populated-role checks prove that unavailable role versions stay omitted. [Three-way library visual](evidence/comparison/role-library-three-way.jpg) places the matched baseline, generated concept and actual final implementation together.

Meeting detail still devotes a large section to the connection explanation before Join call; tutorial still has a prominent introductory callout; Action centre keeps two navigation levels. These are remaining information-density opportunities, not source regressions created by a token change. Calendar/provider behavior and broader navigation changes require a separately reviewed task.

This review supports the bounded local presentation acceptance, with the stated gaps. It does not certify usability gains by user testing, every mobile/state variant, provider connections, new competency PRD functionality or live deployment.
