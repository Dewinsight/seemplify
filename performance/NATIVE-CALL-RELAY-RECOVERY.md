# Native-call relay recovery

A failed TURN credential request previously retained the caller’s newly reserved join slot. The browser had not received a session, so its next join used a new peer ID and could be rejected for 30 seconds. The recovery change releases only the failed acquisition. A server-generated claim identifier and captured presence timestamp protect a newer acquisition or refreshed connection; the other participant, recording and signaling history remain intact. Relay lookup and parent-state checks remain mandatory.

The local browser call tests now simulate only the TURN credential HTTP boundary. They still exercise the real API, database, permissions, consent, two browser peers, media capture, recording, playback and retained notes. The synthetic relay uses a loopback discard address; these checks do not establish external TURN transport, live transcription or AI-provider acceptance. Credentials are never printed. The external TURN credential endpoint separately returned HTTP 200 with a valid response shape from both the local PC and production in about 170 ms.

The first post-merge hosted run failed two native-call tests because the hosted runner’s credential requests timed out after five seconds. Its other 121 browser cases passed. Core deployment was cancelled before its deployment job started while this recovery defect and provider boundary were addressed. The new regression is included in the Core deployment gate.

Validation: 122 legacy, 38 unit and 255 integration tests across 23 suites passed. Independent review replayed all 14 relay regressions and 14 lifecycle checks successfully. Five cold-start browser scenarios passed without retries, retaining real media and storage assertions; TypeScript and scoped lint passed, with two pre-existing lint warnings. The Core workflow YAML parsed successfully. Hosted checks, exact image revisions and normal authenticated live behavior remain separate release verification layers.
