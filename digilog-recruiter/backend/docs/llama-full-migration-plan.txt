Llama Full Migration Plan (Recruiter Backend)

Goal
- Migrate all GPT-4.1 runtime usage in recruiter/backend to Azure-hosted Llama-3.3-70B-Instruct.

Scope
- Core LLM wrappers and environment resolution
- CV parsing AI analysis
- Job generation and requirements
- Interview analysis, summaries, team feedback analysis
- Bias analysis and interview question generation
- AI matching analysis and cache metadata
- LangChain model bootstrap
- AI tool executor, memory classification, chat title generation
- Status/toggle operational endpoints

Phases
1) Configuration Layer
- Set Llama as primary model through explicit and compatibility env vars.
- Keep backward-compatible env keys for safe rollout.

2) Core Service Hardening
- Centralize model config resolution in azureOpenAIService.
- Add robust content extraction and JSON parsing helpers.
- Add compatibility methods used by downstream services:
  - chatCompletion(messages, options)
  - generateCompletion(prompt, options)
- Normalize chat title generation return contract.

3) Downstream Compatibility Fixes
- Update services that depended on brittle parsing or missing methods.

4) Ops/API Compatibility
- Preserve legacy /gpt/* paths.
- Add /ai/* status and toggle aliases.
- Introduce ENABLE_LLM_MATCHING with ENABLE_GPT_MATCHING fallback.

5) Verification
- Validate wrapper initialization against Llama endpoint.
- Validate LangChain bootstrap.
- Validate matching batch analysis and JSON outputs.

Rollback
1. Restore previous model env values.
2. Restart backend.
3. Revert wrapper/config code only if necessary.

Success Criteria
- No runtime AI flow depends on hardcoded GPT-4.1 defaults.
- Active model resolves to Llama deployment.
- JSON-heavy flows remain stable.
- Legacy API compatibility preserved.
