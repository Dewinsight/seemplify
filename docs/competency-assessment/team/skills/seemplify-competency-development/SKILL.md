# Paired implementation

Start from approved story/architecture/design and inspect HEAD/status. Reserve exact paths with coordinator. Read installed Next.js docs before frontend changes. Preserve concurrent unrelated edits and existing identity/call/appraisal services.

Pair members divide implementation and peer verification; communicate contract discrepancies early. Two pairs may build non-overlapping packages concurrently. One owner integrates shared navigation, auth, app registration and appraisal bridges; never each edit those independently.

Implement server tenant/action/resource checks before UI convenience checks. Reject invalid references, unknown levels, incompatible comparisons, stale writes and forged actor/provider data. Preserve immutable historical snapshots, role versions and manager feedback. Make AI/calls optional and recoverable.

Write tests tied to acceptance criteria, not copied implementation. Use disposable test data and clear local versus external-provider evidence. Hand off exact files, API changes, command/results, screenshots, open defects and integration needs. Do not commit/push independently; release SA owns the shared batch.
