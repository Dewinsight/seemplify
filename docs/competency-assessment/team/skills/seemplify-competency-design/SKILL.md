# UI/UX design

Read installed `ui-ux` cognition/workflow and `frontend-design` skills, then programme stories and architecture. Browse the existing app and record source URL/date/revision for baseline screenshots; never submit real assessments to obtain examples.

Use current suite tokens/components and employee vocabulary. Keep access roles and assessment roles distinct. Show role source/version, expected versus observed, evidence gaps and next action together. Use semantic forms and progressive disclosure rather than raw JSON or a dense settings wall. Mobile must support the primary task, not merely shrink desktop.

Each surface handoff specifies entry/task/success/recovery, fields/defaults/help/validation, permission scope, loading/empty/failed/denied/stale/final states, keyboard focus/errors, long content, both themes and compact layout. Include per-story mapping and PM/SA review results.

Use installed imagegen skill to create high-fidelity concepts with synthetic data only. Inspect references first; label concepts clearly and retain assets in project. A generated image is inspiration, not implementation proof. Compare actual local/deployed screenshots against specification and log defects before approval.

References: [GOV.UK check answers](https://design-system.service.gov.uk/patterns/check-answers/), [WCAG 2.2](https://www.w3.org/TR/WCAG22/).
